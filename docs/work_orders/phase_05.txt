======================================================================
1. PHASE PLACEMENT
======================================================================

This work is designated Phase 0.5.

It must begin only after Phase 0 has established repository structure, versioned
contracts, stable identifiers, canonical serialization, source registration,
artifact envelopes, provenance, provider boundaries, workspace persistence,
replay foundations, dependency inventory, and licensing inventory.

It must complete before Phase 1 begins substantive audiovisual ingestion and
source-addressing work.

This placement is intentional. The controlled proof corpus depends on Phase 0
infrastructure for provenance, deterministic generation, licensing records,
artifact identity, and replay. Phase 1 and later phases depend on the corpus as
a stable, known input.

Phase 0.5 is not an analytical phase. It creates source material and hidden
reference material. It must not implement transcription, diarization, discourse
analysis, adjudication, scoring, or annotated-output rendering.

The anticipated sequence becomes:

- Phase 0: Project foundation and evidentiary kernel
- Phase 0.5: Controlled proof corpus and synthetic audiovisual fixture
- Phase 1: Audiovisual ingestion and source addressing
- Phase 2: Transcription and temporal speech evidence
- Phase 3: Speaker diarization and participant identity foundations
- later phases as described in PROJECT_DESIGN.md

The builder must recommend a corresponding PROJECT_DESIGN.md revision but must
not silently rewrite the design document unless explicitly authorized.

======================================================================
2. PHASE GOAL
======================================================================

Create a locally generated, legally usable, reproducible, three-speaker
audiovisual fixture that can serve as the principal controlled proof source for
Ratiocinatus.

The fixture must provide:

- distinct synthetic voices;
- an exact canonical script;
- known speaker assignments;
- known line order;
- known intended pauses and overlaps;
- known acoustic perturbations;
- a simple controlled visual presentation;
- an exact generation manifest;
- hidden reference annotations;
- multiple controlled difficulty variants;
- and a redistributable or clearly bounded licensing package.

The corpus must support independent testing of source registration, audiovisual
ingestion, transcription, timing, diarization, speaker attribution, utterance
segmentation, discourse construction, proposition normalization, argument graph
construction, adjudication, scoring, review, and annotated rendering.

The central proof is:

Given the canonical script, generation policy, voice configuration, and fixed
assembly schedule, the project can generate or regenerate a controlled
audiovisual exchange whose source media, timing references, speaker references,
and hidden analytical ground truth are complete, internally consistent,
validated, and traceable.

======================================================================
3. DESIGN AUTHORITY
======================================================================

Implementation must preserve these PROJECT_DESIGN.md principles:

- evidence before interpretation;
- proposals are not facts;
- uncertainty is a first-class output;
- provider independence;
- local-first operation;
- deterministic authority where feasible;
- replayability;
- and strict separation of observation, interpretation, adjudication, scoring,
  review, and rendering.

The hidden reference package represents the intended construction and expected
conservative interpretation of the fixture. It is not an instruction that later
models must reproduce every interpretation regardless of evidence.

Later analytical systems must be permitted to disagree with a reference item,
mark an item ambiguous, produce a supported alternative, or fail conservatively.

5. REQUIRED OUTPUT VARIANTS
======================================================================

5.1 VARIANT A: CLEAN REFERENCE

Purpose:
Establish the best-case source for ingestion, transcription, diarization, and
speaker attribution.

Requirements:

- three clearly distinct voices;
- no simultaneous speech;
- full scripted wording;
- clean audio;
- controlled loudness;
- no background noise;
- comfortable pauses;
- no clipped phonemes;
- no visual ambiguity;
- and exact line-level schedule.

Canonical suffix: clean

5.2 VARIANT B: NATURALIZED EXCHANGE

Purpose:
Introduce limited realistic conversational complexity without changing the
underlying argument.

Requirements:

- three distinct voices;
- controlled hesitations;
- one self-correction;
- one brief interruption;
- two brief overlap intervals;
- variable pauses;
- limited speech-rate variation;
- one off-camera or visually unhighlighted utterance;
- and no destructive noise.

Canonical suffix: naturalized

The builder may alter delivery but must not alter propositional content except
where this work order explicitly authorizes a naturalized form.

5.3 VARIANT C: ADVERSARIAL EVIDENCE

Purpose:
Test whether later systems expose uncertainty rather than manufacturing
certainty.

Requirements:

- all Variant B characteristics;
- one low-volume line;
- one line with mild broadband background noise;
- one partially clipped initial word;
- one longer overlap interval;
- one deliberately similar voice characteristic between two speakers while
  preserving meaningful distinction;
- one visual active-speaker mismatch;
- and one semantically ambiguous passage.

Canonical suffix: adversarial

Perturbations must be controlled and documented. They must not render the source
generally unusable.

8. TEXT-TO-SPEECH REQUIREMENTS
======================================================================

Use a provider-independent TTS boundary.

The initial preferred candidate is Kokoro or another local system whose software,
model weights, and selected voices are compatible with intended fixture use and
distribution.

Do not assume that an engine license governs every voice or model artifact.

Before generation, record:

- engine name and version;
- code license;
- model name and version;
- model-weight license;
- voice identifiers and voice-specific terms;
- phonemizer dependency and license;
- language and sample rate;
- inference configuration;
- deterministic seed where supported;
- and known reproducibility limitations.

Voice requirements:

- all voices intelligible;
- three voices meaningfully distinguishable;
- no intentional imitation of a known person;
- no voice cloning;
- Participant A and Participant B distinguishable under ordinary diarization;
- Moderator the most acoustically distinct voice.

Multiple engines may be used only if fully documented and necessary.

The canonical fixture may be frozen by content hash even if generation is not
byte-identical across every environment.

25. COMPLETION GATES
======================================================================

SCRIPT GATE

- complete 68-line script present;
- speakers and evidence validate;
- variant changes remain authorized.

VOICE GATE

- three licensed local voices assigned;
- intelligible and distinguishable;
- no cloned or impersonated voice;
- all terms recorded.

MEDIA GATE

- three variants exist;
- final video, mix, and stems exist;
- files open;
- properties match policy.

TIMING GATE

- every line has source times;
- overlaps and perturbations are declared;
- all intervals fall within media duration.

VISUAL GATE

- three-panel presentation exists;
- active-speaker states follow schedule except one declared Variant C mismatch;
- no analytical answers appear.

REFERENCE GATE

- hidden references exist;
- annotations cite valid lines or evidence;
- candidate calls and non-calls are separate;
- ambiguity is explicit;
- no overall winner encoded.

REPRODUCIBILITY GATE

- configuration complete;
- hashes frozen;
- commands preserved;
- regeneration classification accurate;
- identity changes with canonical media changes.

LICENSING GATE

- licenses and notices present;
- selected voices approved;
- no untracked third-party assets;
- distribution status explicit.

VALIDATION GATE

- machine and human reports pass;
- negative cases pass;
- exported-package validation passes.

PHASE-BOUNDARY GATE

- no production transcription;
- no production diarization;
- no discourse analysis;
- no adjudication;
- no scoring;
- no analytical overlay rendering.

29. PHASE 0.5 SUCCESS DEFINITION
======================================================================

Phase 0.5 succeeds when Ratiocinatus possesses a controlled audiovisual source
family that:

- requires no external domain expertise;
- contains known logical and dialectical structures;
- includes bounded conversational difficulty;
- has distinct synthetic speakers;
- has exact timing and provenance;
- has hidden references;
- includes expected ambiguities and expected non-calls;
- is legally usable under documented policy;
- validates independently;
- and serves as the common proof source for Phases 1 through 12.

The desired result is not a demonstration that Ratiocinatus can already judge
the exchange.

The desired result is a trustworthy exchange against which every later claim of
capability can be tested.
