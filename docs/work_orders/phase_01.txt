Document status: Implementation work order

Primary implementation language: Python
Execution model: Local-first

======================================================================
1. PHASE GOAL
======================================================================

Convert complete audiovisual recordings into stable, validated, addressable,
resumable source corpora suitable for all later Ratiocinatus analysis.

Phase 1 must establish the authoritative relationship among the original
recording, its registered source identity, audiovisual streams, selected working
streams, normalized derivatives, processing chunks, source intervals, cache
entries, integrity records, and ingestion reports.

The phase must support recordings potentially several hours in length without
requiring the entire recording to remain in memory or forcing completed work to
be repeated after interruption.

Central proof:

Given a registered audiovisual source, Ratiocinatus can inspect it, select
streams under explicit policy, create validated normalized working derivatives,
divide those derivatives into stable processing chunks, map every derived
interval back to the original source timeline, resume interrupted ingestion
safely, and reproduce or reuse the same corpus under identical source and
configuration.

Phase 1 creates no transcript, speaker identity, discourse interpretation,
logical judgment, score, or analytical video annotation.

6. REQUIRED DELIVERABLES
======================================================================

6.1 MEDIA INSPECTION PROVIDER

Implement a production inspection provider, initially expected to use FFprobe.

Capture where available:

- container format and long name;
- duration and start time;
- bit rate and file size;
- tags, chapters, and programs;
- stream indexes and types;
- codec names, profiles, and levels;
- time bases;
- start timestamps and durations;
- frame rates;
- sample rates;
- channel counts and layouts;
- pixel formats and dimensions;
- sample and display aspect ratio;
- color metadata;
- rotation or display matrix;
- disposition flags;
- language tags;
- default and forced status;
- attachment status;
- and decode-relevant warnings.

Preserve:

- executable identity;
- FFprobe version and build configuration;
- argument array;
- exit code;
- standard error;
- raw JSON hash;
- parsed result;
- and invocation provenance.

6.2 STREAM INVENTORY

Create a canonical stream inventory for every source.

Distinguish:

- video;
- audio;
- subtitle;
- data;
- attachment;
- unknown;
- and unsupported.

Every stream must have a stable source-local identity. All streams remain
visible even when unselected.

6.3 STREAM-SELECTION POLICY

Implement versioned selection policy.

AUDIO DEFAULT:

- explicit configured stream first;
- otherwise default audio stream;
- otherwise first decodable audio stream;
- one authoritative working audio stream;
- no silent mixing of multiple source streams;
- retain all rejected candidates and reasons.

VIDEO DEFAULT:

- explicit configured stream first;
- otherwise default video stream;
- otherwise first decodable non-attached-picture video stream;
- exclude cover art;
- permit audio-only ingestion.

Each decision records:

- candidates;
- eligibility;
- disqualifications;
- ranking factors;
- selected stream;
- policy version;
- determinacy;
- and human-readable explanation.

6.4 DECODE QUALIFICATION

Inspection alone is insufficient.

Qualification must verify:

- source opens;
- selected streams begin decoding;
- representative early, middle, and late regions decode;
- declared duration is plausible;
- and obvious truncation or timestamp failure is detected.

Represent:

- inspection success;
- decode-start success;
- sampled decode success;
- full decode success;
- warning;
- failure;
- and not performed.

6.5 SOURCE TIMELINE MODEL

Represent separately:

- source media time;
- normalized corpus time;
- derivative-local time;
- chunk-local time;
- and wall-clock creation time.

Account for:

- container and stream start times;
- time bases;
- negative timestamps;
- non-zero starts;
- discontinuities;
- audio and video duration differences;
- variable frame rate;
- and timestamp rounding.

Use integer microseconds or another documented exact rational representation.
Floating-point seconds may be exported only for readability.

6.6 SOURCE INTERVAL MAPPING

Support:

- point mapping;
- interval mapping;
- source-to-derivative;
- derivative-to-source;
- chunk-local-to-source;
- and overlap-aware mapping.

Classify mapping results as:

- exact;
- rounded;
- clipped;
- discontinuous;
- unavailable;
- or ambiguous.

Every later token, turn, or frame interval must be recoverable against the
original source timeline.

6.7 AUDIO NORMALIZATION

Create a speech-processing derivative.

Initial policy:

- WAV PCM or FLAC, decided by ADR;
- 16 kHz unless qualification justifies another rate;
- mono;
- signed 16-bit PCM or justified equivalent;
- zero-based normalized time;
- deterministic downmix;
- no denoising;
- no silence removal;
- no voice enhancement;
- no speech isolation;
- no dynamic-range compression;
- no pitch or tempo change;
- no subjective loudness processing;
- and no destructive filtering beyond decode, downmix, and resample.

Preserve:

- selected stream;
- original layout;
- downmix policy;
- resampler;
- output format;
- sample rate;
- sample count where available;
- command;
- tool version;
- duration;
- hash;
- and interval mapping.

The Riverton MP4 mix is the Phase 1 source. Isolated stems are reference assets
and must never be selected automatically.

6.8 VIDEO ACCESS OR NORMALIZATION

Create a stable video access plan and, where policy requires, a remux or
normalized derivative.

The policy must address:

- variable frame rate;
- edit lists;
- rotation;
- non-square pixels;
- unsupported pixel formats;
- damaged timestamps;
- random seek behavior;
- and storage cost.

If transcoding:

- preserve full frame content;
- do not crop;
- do not resize without explicit policy;
- do not burn captions;
- do not alter speed;
- normalize rotation explicitly;
- and record every transformation.

Frame access must be timestamp-based, not frame-number authoritative.

6.9 NORMALIZED CORPUS

Create an `AudiovisualCorpus` or equivalent connecting:

- registered source;
- source fingerprint;
- inspection result;
- stream inventory;
- selection decisions;
- qualification result;
- source timeline;
- normalized audio;
- normalized video access or derivative;
- chunk plan;
- interval maps;
- cache references;
- integrity state;
- configuration;
- and provenance.

The corpus must be independently loadable, exportable, and validatable.

6.10 PROCESSING CHUNK PLAN

Chunks are operational, not semantic.

Support:

- configurable target duration;
- configurable overlap;
- minimum and maximum duration;
- stable IDs;
- exact intervals;
- contiguous ordinals;
- terminal-short-chunk handling;
- audio chunks;
- and video seek windows.

Initial default:

- 10-minute target;
- 5-second overlap;
- zero-based corpus-time boundaries;
- no silence-based cutting;
- no content-aware cutting.

Changing policy creates a new chunk-plan identity.

6.11 CHUNK MATERIALIZATION

Support:

- virtual interval chunks;
- and materialized files only when providers require them.

Record:

- why materialized;
- source derivative;
- interval;
- codec or sample format;
- exact command;
- expected and actual duration;
- hash;
- and integrity result.

6.12 CACHE

Implement content- and configuration-addressed cache for:

- inspection;
- qualification;
- selection;
- normalized derivatives;
- corpus manifests;
- chunk plans;
- materialized chunks;
- interval maps;
- and reports where appropriate.

Keys include:

- source fingerprint;
- operation and version;
- relevant configuration;
- provider identity and version;
- external tool version where material;
- and format version.

Represent:

- hit;
- miss;
- invalid;
- stale;
- corrupted;
- incompatible;
- bypassed;
- and rebuilt.

Validate before reuse.

6.13 RESUME AND RECOVERY

Persist stages:

- source verified;
- inspection committed;
- selection committed;
- qualification committed;
- audio normalization committed;
- video access committed;
- timeline committed;
- chunk plan committed;
- corpus committed;
- reports committed;
- and complete.

Resume must:

- locate latest valid stage;
- validate outputs;
- reuse valid outputs;
- rebuild missing or invalid outputs;
- preserve failed attempts;
- and never report success before corpus and reports commit.

Handle:

- process interruption;
- cancellation where supported;
- write failure;
- full disk;
- external-tool error;
- corrupt partial output;
- changed source;
- changed configuration;
- changed tool version;
- and unsupported format version.

6.14 INTEGRITY VALIDATION

Validate:

- source hash;
- inspection attachment;
- stream references;
- selected streams;
- derivative files and hashes;
- derivative decodability;
- duration agreement;
- sample and frame plausibility;
- mapping bounds;
- chunk coverage and overlap;
- cache consistency;
- lineage;
- and corpus completeness.

Detect:

- gaps;
- unintended overlaps;
- out-of-bounds intervals;
- negative normalized intervals;
- impossible duration relationships;
- missing provenance;
- stale source;
- and derivative substitution.

6.15 REPORTS

Produce machine-readable and human-readable:

- inspection report;
- stream-selection report;
- decode-qualification report;
- normalization report;
- timeline report;
- chunk-plan report;
- cache report;
- integrity report;
- resume/recovery report where applicable;
- normalized-source report;
- and completion report.

10. AUDIO INVARIANTS
======================================================================

- remove silence;
- suppress noise;
- isolate voices;
- selectively equalize speech;
- alter tempo or pitch;
- repair clipping;
- remove overlap;
- or apply automatic gain control that changes evidence.

Downmix policy must be documented and avoid clipping.

Test:

- stereo;
- mono;
- multichannel;
- audio-only;
- multiple audio streams;
- no audio;
- and unusual sample rates.

- rotation;

======================================================================
24. PHASE 1 SUCCESS DEFINITION
======================================================================

Phase 1 succeeds when Ratiocinatus can accept a complete audiovisual recording
and produce a trustworthy, portable, addressable corpus in which:

- the original source is unchanged;
- every stream is known;
- selected streams are explicit;
- normalized derivatives are validated;
- time domains are unambiguous;
- derived intervals map back to source evidence;
- long recordings are divided into stable operational chunks;
- cache reuse is safe;
- interrupted work resumes without silent duplication or loss;
- integrity failures are visible;
- and later phases can consume the corpus without reopening settled ingestion
  questions.

The desired result is not a transcript.

The desired result is the complete, stable audiovisual ground on which every
later transcript, speaker attribution, proposition, call, and score can stand.
